# Design principles

## The conversation is the product

The primary surface stays a focused chat column. The 52px collapsed rail is an entry point, not a navigation system. Workflow machinery should appear only when it has something useful to say.

## Status is transient and expandable

An active request gets a compact status row. Its public activity record expands on demand; it is not a permanent dashboard, progress board, or admin console.

## Every change needs a public rationale

The system should make the request, policy outcome, candidate work, validation, deployment result, and any refusal inspectable. Transparency is a functional constraint, not decoration.

## Live, malleable software

Bret Victor's work is an inspiration: software should make its behavior and consequences more immediate, inspectable, and malleable. Livework borrows that direction, not an aesthetic. The bar is a tight feedback loop between a request, visible work, and a real result.

## Do not reward machinery

More panels, charts, queues, and controls do not make an evolving system more trustworthy. Evidence, bounded authority, and a calm interface do.
